## Three post ideas
- A real task: ask the assistant to draft a daily plan and show the output.
- Behind the build: a short, honest developer diary showing one feature being improved.
- Feedback request: ask testers what was confusing, what crashed, and which feature they used most.

## First-month checklist
- [ ] Ask 5–10 trusted testers to install and test the beta.
- [ ] Publish 3–5 short videos showing real features.
- [ ] Record views, link clicks, successful installs reported by testers, and crash reports.
- [ ] Fix the top three issues before spending money on promotion.
- [ ] Never buy fake downloads, spam groups, or promise features that do not exist.

## Safety and release notes
The current workflow builds a **debug APK**. It is suitable for beta testing only; do not present it as a production-signed release. Before wider public distribution, review API-key handling, backend rate limiting and cost controls, privacy disclosures, Firebase setup, and device testing. Because the project owner is under 18, ask a parent/guardian to help with any platform accounts, contracts, payment setup, or public launch requirements that have age restrictions.
